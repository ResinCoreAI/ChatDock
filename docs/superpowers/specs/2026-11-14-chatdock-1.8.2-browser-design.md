# ChatDock 1.8.2: the Browser tab

Date: 2026-11-14 · Status: approved by the founder (2026-11-14)
Mock (approved look): `docs/search-mocks/`

## Why

People who play games need to look things up (a boss, a build, patch notes) without Alt+Tab.
ChatDock already sits at the screen edge, so it gets a Browser tab: push the mouse to the edge, search,
read the page in the panel, and go back to the game. Nothing opens outside unless the user asks.

## What the founder decided

- The Browser is **added from the "+" menu** (first row, "Browser"). It is off after install.
- The start page is **our own**: a search box, a row of search engines to pick from, shortcuts, recent searches.
- **Several search engines** to choose from; the choice is remembered.
- **Pages open inside the panel**, not in the computer's browser.
- **Several pages at once** in the Browser's **own tab strip**, under ChatDock's app tabs and kept apart from them.
- Suggestions while typing are **on by default** and can be turned off in Settings.
- Typing a web address opens that site directly.

## The user's view

### Adding and removing
- "+" menu: first row "Browser" (search icon, accent colour, hint "ค้นหาเว็บ"), then a separator, then the chat apps that are off.
- Once added, the Browser tab sits after the chat apps in ChatDock's tab strip.
  Right-click it for "Close Browser" (the same as turning an app off).
- Ctrl+1..9 counts it like any other tab.

### Inside the Browser tab (top to bottom)
1. **Browser tab strip** (36 px): one small tab per page (site icon, title, ✕), "+" for a new tab.
   It is lighter and smaller than ChatDock's app tabs, so the two never read as one strip.
2. **Navigation row** (42 px): back, forward, reload, the address field, home, and "open in the computer's browser".
3. **The page**: either our start page or a real web page.

### Start page (a new tab shows it)
- The ChatDock logo and "Browser".
- The search box, with the current engine's icon on its left (clicking the icon steps to the next engine).
- Engine chips: Google, Bing, DuckDuckGo, YouTube, Brave, Wikipedia. Wikipedia uses the UI language's site.
- Shortcuts: up to 12 tiles. "Add" opens a small form (name, address). ⋯ or right-click edits or deletes.
  New installs start with YouTube, Gmail, GitHub, Twitch, Shopee and Netflix.
- Recent searches: the last 8, each with the engine it used, ✕ to remove, "Clear all".
- A footer line: pages open in this panel, no need to leave the game.

### Typing
- A list drops under the box:
  1. If the text is a web address, the first row is "open <address>".
  2. Matching recent searches.
  3. The text itself, searched with the current engine.
  4. Up to 5 suggestions from the current engine.
- Arrow keys move through the list. Enter picks. Esc closes the list, and a second Esc clears the box.
- **What counts as an address:**
  - `http(s)://…`, `localhost[:port]`, or `name.tld[:port][/path]` with no spaces.
  - Everything else is a search.

### Pages
- A search opens the engine's results page in the current Browser tab.
- Links that would open a new window (`target=_blank`, `window.open` after a click) open as a new Browser tab next to the current one.
- **The address field** shows the page's address and works as a second search box:
  - Ctrl+L selects it.
  - Enter opens an address, or searches with the current engine.
- The tab title and icon follow the page (title from `DocumentTitleChanged`, icon from `FaviconChanged`).
  Until an icon arrives, the tab shows a letter tile.
- **Loading**: a spinner on the tab icon and a 2 px bar under the navigation row.

### Shortcuts (only while the Browser tab is open)

| Key | Action |
|---|---|
| Ctrl+T | New Browser tab |
| Ctrl+W | Close the current Browser tab (elsewhere it still hides the panel) |
| Ctrl+L | Address field |
| Alt+← / Alt+→ | Back / forward in the current Browser tab |
| Ctrl+R / F5 | Reload the page |
| Ctrl+PgUp / Ctrl+PgDn | Previous / next Browser tab |
| Middle click on a tab | Close it |

- Ctrl+Tab keeps switching ChatDock's apps, as today.

### Remembering
- **Kept in settings.json:** the open Browser tabs (address and title), which one is open, the engine, shortcuts, recent searches, and the two switches.
- **After a restart:** only the open tab loads. The others load when clicked.
- **Settings → a new "Browser" page:**
  - Suggestions while typing (on). The line under it says the typed text goes to the chosen engine.
  - Remember searches (on). Turning it off also clears them.
  - Clear browsing data (cookies and cache of the Browser only, never the chats).

## How it is built

### Where things are drawn
- **In the panel page (ui/panel.html):** the Browser's tab strip, navigation row and start page.
  They are a new section, `#browser`, with its own `browser.js` / `browser.css`, so panel.js does not grow much.
- **Web pages:** WebView2 controllers stacked over the panel page, like the chat views today.
  - Their top edge moves down by the Browser bar height (78 px × UI scale) under the header (and banner).
  - When the open Browser tab shows the start page, Rust hides every Browser view, so the panel page is seen.
    This is the same mechanism as `settings_mode`.

### "browser" is not a catalog app
- **The tab id is `browser`.** The places that assume a catalog entry get a Browser case:
  - `ui_state`, which today unwraps `apps::get`.
  - `is_enabled` / `enabled_apps`: the Browser comes last.
  - The "+" menu (`menu.rs open_add_menu`, `ui_state.more`).
  - `set_app_enabled`.
  - `create_view` keeps refusing non-catalog ids; Browser views use their own creation path.
- **A new Rust module, `browser.rs`, owns:**
  - the Browser tabs (a list of `{ id, url, title, controller?, last_used }`) and which one is open
  - creating, closing, navigating and laying out Browser views
  - suggestions
  - its settings
  - `chats.rs` stays the chat views' module.

### A separate browser for the Browser (recommended)
- **Each Browser view uses its own WebView2 environment** with its own data folder (`data_dir/WebView2-browser`) and its own browser process. It is not the panel page's environment.
- **Why:**
  - **Cookies:** sites the user visits never share a profile, cookies or a process with the logged-in chats.
  - **Crashes:** a crash in a web page cannot restart the chats.
  - **Security settings:** this environment can run with the safer defaults the chats switched off. SmartScreen and reputation checking stay **on**; autoplay needs a click.
- **Cost:** one more browser process (roughly 60–100 MB) while the Browser is open.
  It is not started until the Browser tab is first opened.
- **Other changes this needs:**
  - `is_chat_browser_window` also counts this process's windows, so focus and auto-hide treat them as ChatDock's own.
- **The other way:** a separate profile in the shared environment. Lighter, but it gives up all three points above.

### Rules for Browser views (their own `configure`, not the chats')
- **Navigation:** any `https://` or `http://` site. Addresses on this PC or the local network are still refused.
  This reuses `block_this_pc`, minus its "all plain http" rule.
  Other schemes (`mailto:`, `steam://` and so on) ask before opening the program; nothing opens without a click.
- **New windows** after a click: a new Browser tab. The window is handed over with `SetNewWindow`, so sign-in pop-ups that use `window.opener` keep working.
  Without a click: refused.
- **Permissions:** with no prompt UI in 1.8.2, everything is refused.
  That covers mic, camera, location, notifications, clipboard read and MIDI.
  Fullscreen video is allowed and fills the panel's page area.
- **Downloads:** refused. A small bar under the navigation row says the file can't be saved here and offers "Open in the computer's browser".
- **SITE_SCRIPT** (call detection, volume, passkey block) is **not** injected. Passkeys are allowed: no chat login is at risk in this environment.
- **Right-click menu:** ChatDock's own, with Browser rows added:
  - Back, Forward, Reload
  - Open link in a new tab, Copy link, Copy, Paste
  - Open in the computer's browser
- **Saving passwords and autofill:** off, as in the chats.

### Memory
- **Hidden Browser views** (another Browser tab, another app, the start page, the panel hidden) get the LOW memory target.
  The exception is a page playing sound.
- **Unused Browser tabs:** a tab unused for 30 minutes drops its view and keeps its address and title. Clicking it reloads.
  The open tab and one playing sound are never dropped.
- **Limit:** at most 10 Browser tabs. "+" is disabled at 10, with a tooltip.

### Suggestions
- **Fetched by Rust**, not the page (no CORS, no cookies, never through our server).
  The request goes only to the current engine's suggestion address:
  - Google: `suggestqueries.google.com/complete/search?client=firefox&q=`
  - Bing: `api.bing.com/osjson.aspx?query=`
  - DuckDuckGo: `duckduckgo.com/ac/?q=`
  - YouTube: Google's endpoint with `ds=yt`
  - Brave: `search.brave.com/api/suggest?q=`
  - Wikipedia: `<lang>.wikipedia.org/w/api.php?action=opensearch&search=`
- **Limits:** 150 ms after the last key, at most one request in flight, 2 s timeout, nothing sent when the switch is off.
  Answers older than the current text are dropped.
- **Parser:** one for the OpenSearch shape `[q, [s…]]` and one for DuckDuckGo's `[{phrase}]`, both unit tested.
  If an engine changes its format, the list just shows no suggestions.

### IPC (panel page ↔ Rust, new channels)
- **Page → Rust:**
  - `browser:go {text}` (Rust decides address or search)
  - `browser:open {url, newTab}`
  - `browser:tab {id}`, `browser:close {id}`, `browser:new`
  - `browser:back`, `browser:forward`, `browser:reload`, `browser:home`, `browser:outside`
  - `browser:suggest {text}`
  - `browser:set {key, value}`, checked by `pref_ok`-style rules
- **Rust → page:**
  - `browser:state` (tabs with titles, icons, loading flag, can-go-back/forward, open tab, current address)
  - `browser:suggest {text, items}`
  - `browser:download-refused {name}`

### Settings (settings.json)
```json
"browser": {
  "engine": "google",
  "suggest": true,
  "remember": true,
  "recent": [{ "q": "…", "e": "google" }],
  "shortcuts": [{ "n": "YouTube", "u": "youtube.com" }],
  "tabs": [{ "url": "…", "title": "…" }],
  "open": 0
}
```
- **Defaults** are merged by hand in `Settings::load`, like `apps`.
- **Limits:** recent searches 8, shortcuts 12, tabs 10.
- **Validation:** every string has a length cap. Shortcut and tab addresses must be http(s).
- **Turning the Browser off:** closes its views and forgets the tabs. Shortcuts, engine and recent searches stay.

### Text
- Every new string is in all five languages in `ui/i18n-data.js`, which must stay strict JSON.
- 1.8.2 adds a test that every language has the same keys. None exists today.

## Out of scope for 1.8.2
- Bookmarks and history pages
- Downloads
- Extensions
- Password saving
- Private mode
- Permission prompts
- Find in page (Ctrl+F)
- Zoom per site
- Dragging tabs to reorder them
- Moving a Browser tab out to its own window

## Decided after review (2026-11-14)
1. **A separate browser process** for the Browser, as recommended above.
2. **Videos do not keep the panel open.** The panel auto-hides as usual and the sound keeps playing.
