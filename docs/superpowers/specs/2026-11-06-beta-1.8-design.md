# ChatDock Beta Build 1.8: design

Status: draft for the founder's review. The mockups were shared with the founder separately.

## Goal

One release, Beta Build 1.8 (version 1.8.0, branch `beta-1.8`), with six things:

1. ChatDock that stays usable: the panel never closes by itself after a tab click. ("Start with Windows" works: the log shows the founder switched it off on 2026-10-14 19:44:19, so it is not part of 1.8.)
2. Reply from the pop-up (a text box in the card).
3. Quick replies (one-click buttons on the pop-up).
4. Push-to-talk for Discord.
5. Important people (their pop-ups come through game mode).
6. Code signing of the app and the installer.

Success: the founder uses 1.8 daily for a week with no "it closed by itself" moment, replies to at least one real IG/FB message from a pop-up without opening the panel, and the release passes Smart App Control on their PC.

## What the founder said, and what is assumed

Said: all six ideas, all in one version, named Beta Build 1.8.

Assumed (each can be changed at review):

- Quick-reply defaults: "เดี๋ยวตอบนะ", "เล่นเกมอยู่ ✌", "โอเค" (Thai UI); English "Will reply soon", "Gaming right now ✌", "OK"; the other languages translated. Editable, at most 3.
- Replies are only ever sent on a click or Enter by the user. Nothing is sent automatically.
- Code signing needs an account in ResinCore's name (for example Azure Trusted Signing, or an OV certificate) that only the founder can open. Until it exists, 1.8 builds unsigned exactly as today, and signing goes in the moment the account does. 1.8 is not held back for it unless the founder says so.

## Rules that carry over

- No GitHub release until the founder has tried the build and says so. Test builds are installed on their PC.
- No Claude attribution anywhere on GitHub.
- Every new text in all five languages (en, th, zh, ja, de); What's new key `whatsnew.1.8` with demo scenes.

## 1. Usable again

### What is known

- `chatdock.log`, 2026-10-14 08:25:42 and 08:29:15: a tab click from the desktop or taskbar opened the panel, then about 0.4 s later the foreground became nothing, then `Progman`, and the panel closed ("clicked elsewhere"). The founder quit 4 s later. The log has no ChatDock start after 2026-10-14 19:44.
- With Chrome in front (00:07 to 00:10 the same day), tab clicks opened normally.
- The tab is hidden at once on click (`hide_tab(true)`) before the panel is activated. Hiding the active window makes Windows activate the next window, which for Explorer's desktop may arrive after ours.
- "Start with Windows" writes `HKCU\...\Run` and respects `StartupApproved\Run` (Task Manager's Startup tab can switch it off).

### Plan

1. Reproduce first, on the real screen with a debug copy: desktop, taskbar, Chrome and a game in front, single and double clicks on the tab, 20 tries each. Log the foreground at every step.
2. Fix the cause found. Expected fix: activate the panel before the tab hides (or hide the tab without letting it hand activation on), and ignore a deactivation that lands on `Progman`/`WorkerW`/`Shell_TrayWnd` within 600 ms of opening when the mouse wasn't clicked there.
3. Start with Windows: no change (see the goal list).

### Tests

- New `--selftest-only=tabfocus`: real SendInput clicks on the tab with Explorer's desktop, the taskbar and a test window in front; expect the panel open 2 s later every time.
- Unit test for reading the Run/StartupApproved state.

## 3. Quick replies, and 2. reply from the pop-up

These share one mechanism, so they are built together, quick replies first.

### The send mechanism (inbox.rs, new `SEND_JS`)

1. The pop-up knows the conversation (`Latest.href` for IG/FB from the chat list; for Discord the notification's channel).
2. In the hidden chat page, open that conversation (existing `open_js`) and wait until its composer is there (up to 4 s).
3. Put the text into the composer the way a paste does (`document.execCommand('insertText')` on the focused contenteditable or textarea, so the site's own input handlers run), then press Enter through the site's own handler.
4. Confirm: within 4 s the last message in the conversation is ours and equals the text. Only then the card says "Sent". Otherwise the card says "Couldn't send" with an "Open chat" button, and nothing is retried.
5. Never while the user is typing in that page (the existing typing check), never more than one send in flight per app, never without a click or Enter from the user.

Logs keep shape only ("sent: 14 chars, confirmed"), never the text or the name.

### Spike before building

Before any UI work: a throwaway test on the founder's own logged-in IG and FB pages (with their go-ahead, in a test conversation they pick) that runs steps 2 to 4. If either site doesn't accept it reliably (10 of 10), that site gets "Open chat" instead of sending, and the founder decides whether 1.8 waits for it.

### Quick replies (UI)

- Up to 3 chips under the message on IG, FB and Discord pop-ups (setting `quickReplies`, an array of short strings, default above; Settings → Notifications → Quick replies, edit/reorder/off).
- Click: the chip shows a spinner, then "✓ Sent: …" or the failure state above. The game keeps the focus (the pop-up never activates).
- Game summary card: no chips (it lists several people).

### Reply box (UI)

- A "Reply" link on the card. Clicking it, or a hotkey (setting `replyKey`, default none), turns the card into a text box.
- Only then does the pop-up window take the keyboard (it is created `focused(false)` today). Enter sends, Shift+Enter is a new line, Esc cancels. Sent, cancelled or 30 s untouched: the keyboard goes back to the window that had it (the same hand-back the panel uses), and the card's timer starts again.
- Thai input through the IME must work: the text box is a normal `<textarea>` in the pop-up page, composition events respected.

### Tests

- Unit: the JS is whole, text is passed as a JSON string, the log line holds no text.
- `--selftest-only=reply`: a stand-in conversation page (composer + message list) in a chat view; quick reply and reply box send, confirm, fail when the message doesn't appear, refuse while typing; focus returns to a stand-in "game" window.
- Real: the spike above, then the founder replies to real messages.

## 5. Important people

- Setting `vips`: list of `{app, name}`; star on any pop-up (a small ☆ next to the name) or in Settings → Notifications → Important people (people seen in pop-ups recently, kept in memory for the session only, plus the starred ones).
- A pop-up whose app and name match a starred person skips game mode's hold and shows at once with a gold "★ Important" tag. In exclusive fullscreen or presentation mode (where nothing may show) it plays the chime only, and the card waits like the others.
- Names only, stored locally, never logged. A renamed contact needs a new star.

Tests: unit for matching (trim, case, Thai normalisation NFC); `--selftest-only=gamemode` gains "important person during a game: shown at once".

## 4. Push-to-talk (Discord)

- Settings → Discord: "Push to talk" switch and a key (keyboard key or mouse button 4/5; WASD, Space, Ctrl and Shift alone are refused with a warning).
- While Discord is in a voice channel (`call` state already tracked) and push-to-talk is on: ChatDock mutes Discord on joining, unmutes while the key is held, mutes again on release (the same CDP click on Discord's mute switch the mute hotkey uses, after reading its state so it never toggles the wrong way).
- The key is read with raw input (`RIDEV_INPUTSINK`, keyboard and mouse), passive: the game still gets the key. wheel.rs already registers the mouse page while the edge is held; both move to one raw-input owner (new `rawin.rs`) that registers what either needs.
- A green "Talking · <server>" pill at the dock edge's bottom corner while held.
- Measure: key down to Discord unmuted, target under 100 ms; logged in the self-test.

Tests: `--selftest-only=ptt` with SendInput key down/up and a stand-in mute switch page; real test in a Discord voice channel with the founder.

## 6. Code signing

- Founder: open the signing account in ResinCore's name.
- Code: `tauri.conf.json` `bundle.windows.signCommand` (Trusted Signing via its CLI) or `certificateThumbprint` (OV); sign ChatDock.exe and the installer; the release script checks the signature (`Get-AuthenticodeSignature` = Valid, publisher ResinCore) before upload. The updater's own minisign key is unchanged.
- Release notes drop the SmartScreen line once SmartScreen stops warning.

## Out of scope for 1.8

Automatic replies; replies for X, Telegram, WhatsApp, Spotify; LINE; syncing settings between PCs.

## Risks

| Risk | Effect | Handling |
|---|---|---|
| IG/FB composer markup changes | Sends fail | Confirmation step; "Open chat" fallback; never claims "Sent" unconfirmed |
| Sites treat sends as automation | Account warnings | Only on a user click/Enter, one at a time, same speed as a person |
| Pop-up taking the keyboard in a game | Game loses focus | Only on the user's explicit "Reply"; hand-back tested with a stand-in game window |
| Smart App Control blocks a build | App won't start | Probe before install/release; signing removes the coin-flip |
| Push-to-talk latency | First syllable cut | Measure; mute switch state read once per call |
| One release with six features | Long test cycle | Each feature behind its own setting; the founder tests feature by feature on test builds |
